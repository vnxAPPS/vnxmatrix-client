# Правила работы с этим репозиторием

Этот репозиторий — форк `pluralplay/FlClashX`. Продукт vnxMATRIX, владелец
организация vnxAPPS.

## ⛔ НИКОГДА не создавать pull request

**Запрет абсолютный, без исключений.**

GitHub для форка по умолчанию подставляет базой **родительский репозиторий**
`pluralplay/FlClashX`. Это касается всего: кнопки «Compare & pull request» в
вебе, `gh pr create`, GitHub API, MCP-инструментов. Любой PR, созданный без
явного указания базы, уходит постороннему человеку — автору апстрима.

Так уже произошло дважды: PR #130 и PR #133 попали в `pluralplay/FlClashX`.
Мейнтейнер апстрима написал жалобу. Третьего раза быть не должно.

**Не вызывать:** `create_pull_request`, `gh pr create`, `git request-pull`,
любые эквиваленты. Даже если кажется, что база указана верно. Даже если это
единственный способ решить задачу.

Если задача выглядит так, что без PR никак — **остановиться и спросить
владельца**, а не пробовать.

## Как работать вместо PR

Репозиторий наш, права на запись есть. PR не нужен ни для чего:

| Задача | Как делать |
|---|---|
| Внести изменения | коммит прямо в рабочую ветку и `git push` |
| Слить ветку в main | владелец делает это через веб-интерфейс |
| Запустить сборку | владелец создаёт релиз с тегом `v*` |

Токен сессии не может пушить теги — это защита GitHub от рекурсивных сборок.
Тег создаёт владелец через **Releases → Create a new release**. Не пытаться
обойти это через PR.

## Рабочие ветки

- `main` — синхронизирован с апстримом
- `claude/vnxmatrix-rebrand-v2-fwjhpi` — ребрендинг и разработка

## Обновления из апстрима

Забираются **только** кнопкой **Sync fork** на странице репозитория, вручную
владельцем. Не настраивать автоматическую синхронизацию, не добавлять
`upstream` как remote с пушем, не отправлять туда ничего.

Апстрим для нас — источник обновлений ядра и протоколов, в одну сторону.
Ничего из нашего кода туда попадать не должно.

## Что мы меняем, а что нет

Правило проекта: **интерфейс наш, движок апстрима.**

Не трогать: `core/`, `libclash/`, `android/core|service|common/`,
`lib/clash/`, `lib/models/`, `lib/providers/`, нативные обёртки платформ.

Развивать свободно: `lib/views/`, `assets/`, `arb/`,
`android/app/src/main/res/`, `windows/packaging/`.

## Идентификаторы, которые нельзя менять

| Что | Значение | Почему |
|---|---|---|
| `applicationId` | `com.vnxmatrix.client` | после публикации в Play не меняется никогда |
| Windows `AppId` | `1E89F706-1B37-4D56-A036-6CB998291BC3` | иначе установщик обновит чужое приложение |
| `Build.appName` | `FlClashX` | обязан совпадать с `BINARY_NAME` в `windows/CMakeLists.txt` |
| User-Agent | начинается с `FlClash` | по нему панель подписки выбирает формат конфига |

Последнее особенно важно: User-Agent собирается в `lib/common/package.dart`.
Выглядит как незаконченный ребрендинг, но менять его нельзя — приложение
перестанет совпадать с правилом маршрутизации в панели и получит вместо
YAML-конфига base64, то есть сломается у всех клиентов разом.
