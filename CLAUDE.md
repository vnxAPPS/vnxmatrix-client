# Правила работы с этим репозиторием

Этот репозиторий — форк `pluralplay/FlClashX`. Продукт vnxMATRIX, владелец
организация vnxAPPS.

## ⛔ НИКОГДА не создавать pull request

**Запрет абсолютный, без исключений.**

GitHub для форка по умолчанию подставляет базой **родительский репозиторий**
`pluralplay/FlClashX`. Это касается всего: кнопки «Compare & pull request» в
вебе, `gh pr create`, GitHub API, MCP-инструментов. Любой PR, созданный без
явного указания базы, уходит постороннему человеку — автору апстрима.

Так уже произошло дважды: PR #130 и PR #133 попали в `pluralplay/FlClashX`.
Мейнтейнер апстрима написал жалобу. Третьего раза быть не должно.

**Не вызывать:** `create_pull_request`, `gh pr create`, `git request-pull`,
любые эквиваленты. Даже если кажется, что база указана верно. Даже если это
единственный способ решить задачу.

Если задача выглядит так, что без PR никак — **остановиться и спросить
владельца**, а не пробовать.

## Как работать вместо PR

Репозиторий наш, права на запись есть. PR не нужен ни для чего:

| Задача | Как делать |
|---|---|
| Внести изменения | коммит прямо в рабочую ветку и `git push` |
| Слить ветку в main | владелец делает это через веб-интерфейс |
| Запустить сборку | владелец создаёт релиз с тегом `v*` |

Токен сессии не может пушить теги — это защита GitHub от рекурсивных сборок.
Тег создаёт владелец через **Releases → Create a new release**. Не пытаться
обойти это через PR.

## Рабочие ветки

- `main` — состояние апстрима на момент форка (0.4.2)
- `claude/vnxmatrix-rebrand-v2-058` — **текущая разработка**: ребрендинг поверх
  апстрима v0.5.8
- `claude/vnxmatrix-rebrand-v2-fwjhpi` и `release/play-beta` — прежняя линия на
  0.4.2, в ней ядро не стартует на Android (служба `:remote`)
- `release/**` — боевые сборки, ключ подписи обязателен

История апстрима переписана: 0.4.2 не является предком 0.5.x, поэтому обновление
делается переносом наших правок на новый тег, а не слиянием.

## Обновления из апстрима

Забираются вручную, по решению владельца: кнопкой **Sync fork** или, когда
истории разошлись, получением тега по ссылке
(`git fetch https://github.com/pluralplay/FlClashX refs/tags/vX.Y.Z`). Не настраивать автоматическую синхронизацию, не добавлять
`upstream` как remote с пушем, не отправлять туда ничего.

Апстрим для нас — источник обновлений ядра и протоколов, в одну сторону.
Ничего из нашего кода туда попадать не должно.

## Что мы меняем, а что нет

Правило проекта: **интерфейс наш, движок апстрима.**

Не трогать: `core/`, `libclash/`, `android/core|service|common/`,
`lib/core/`, `lib/models/`, `lib/providers/`, нативные обёртки платформ.

Исключение: название приложения в 0.5.8 задаётся ресурсом `app_name` в
`android/common/src/main/res/values/strings.xml` — эту строку менять можно и
нужно.

Развивать свободно: `lib/views/`, `assets/`, `arb/`,
`android/app/src/main/res/`, `windows/packaging/`.

## Идентификаторы, которые нельзя менять

| Что | Значение | Почему |
|---|---|---|
| `applicationId` | `com.vnxmatrix.client` | после публикации в Play не меняется никогда |
| `uaAppName` в `lib/common/constant.dart` | `FlClashX` | по началу User-Agent панель выбирает формат конфига |
| `Components.PACKAGE_NAME` в `android/common` | `com.follow.clashx` | это пространство имён классов и имя каналов, не имя пакета приложения |
| `namespace` в `android/app/build.gradle.kts` | `com.follow.clashx` | от него зависят имена классов и JNI-функций ядра |
| Windows `AppId` | `1E89F706-1B37-4D56-A036-6CB998291BC3` | иначе установщик обновит чужое приложение |

Про User-Agent подробнее: в 0.5.8 он собирается в `lib/common/package.dart` как
`'$uaAppName/v<версия> core/<mihomo> Platform/<os>'`. Апстрим подставлял туда
`appName`; у нас `appName = 'vnxMATRIX'`, и с ним User-Agent перестал бы
начинаться с `flclash`. Панель отдала бы base64 вместо YAML, и приложение
сломалось бы у всех клиентов разом. Проверка `guard` в
`.github/workflows/android-release.yaml` следит за этим на каждом пуше.

## Сборка и проверка

- `.github/workflows/android-release.yaml` — AAB для Play, APK для ручной
  раздачи и дымовой тест на эмуляторе с logcat и скриншотами в артефактах.
- Суффиксы `.pre` и `.dev` Gradle апстрима добавляет к имени пакета молча:
  `.pre` — если не передан `APP_ENV=stable`, `.dev` — если нет ключа подписи.
  Шаг «Имя пакета в собранном APK» это проверяет.
- `versionCode` = номер сборки (минуты с 2026-01-01 UTC) + 5000 от апстрима.
